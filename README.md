# 🤖 AI-Service (Agent 2: News & Sentiment)

This microservice is a FastAPI application that acts as an autonomous **AI Research Assistant**. It uses **LangGraph** and **Google Gemini 1.5 Flash** to automatically scour the web, read financial news, gauge social media sentiment, and summarize market data for any stock ticker you give it. 

It is fully containerized, uses a persistent PostgreSQL database to store its findings, and exposes its features through a lightning-fast API.

---

## 🏗️ Architecture & File Structure

This service is cleanly structured using modern Python and FastAPI best practices to keep the code organized and scalable:

*   **`src/main.py`**: The main entry point that boots up the Uvicorn server and wires all the routes together.
*   **`src/routers/routes.py`**: Contains all of the API endpoints (`/analyze`, `/history`, `/news`).
*   **`src/database.py`**: Manages the SQLAlchemy connection to our shared PostgreSQL database (`shared_test_db`) and defines the table structures.
*   **`src/schemas.py`**: Contains Pydantic models (blueprints) to validate incoming API requests and ensure users send the correct data format.
*   **`src/agent2_graph.py`**: The LangGraph workflow that orchestrates the AI agent's thought process, tools, and decision making.

---

## 🛠️ Core Technologies Used

*   **FastAPI:** Powers the high-performance API endpoints and automatic Swagger documentation.
*   **LangGraph & LangChain:** Orchestrates the AI's "thought process" and manages the state between gathering data and analyzing it.
*   **Google Gemini 1.5 Flash:** The core Large Language Model (LLM) that reads all the raw data and extracts insights, sentiment, and conviction scores.
*   **SQLAlchemy (ORM):** Manages the Python-to-PostgreSQL database connection and enforces data integrity.
*   **PostgreSQL:** The shared database engine (`shared_test_db`) where historical analyses and news are permanently stored.
*   **uv:** A blazing fast Python package installer used during the Docker build process.
*   **Docker:** Containerizes the service so it runs consistently anywhere and communicates via the `trading_network`.

## 🧠 The LangGraph Agent Workflow

When a stock ticker is submitted, the AI uses custom-built **Tools** to pull real-time data from the internet before making a decision. 

### Custom Agent Tools:
1.  **NewsAPI Tool (`fetch_financial_news`)**: Scrapes the latest financial news articles and headlines regarding the specific stock ticker using `newsapi-python`.
2.  **Reddit Tool (`fetch_reddit_sentiment`)**: Connects to the Reddit API (via `PRAW`) to pull live discussions and gauge retail investor sentiment from financial subreddits.
3.  **Twitter/X Tool (`fetch_twitter_sentiment`)**: Connects to the Twitter API (via `Tweepy`) to capture real-time social media sentiment and trending narratives.

### How it Thinks (Optimized):
1.  **Gather Data Node**: The agent activates the 3 tools above simultaneously using a `ThreadPoolExecutor` to pull raw JSON data from all three platforms concurrently for maximum speed.
2.  **Analyze Node**: All that raw text is dumped into a massive prompt for **Gemini 1.5 Flash**. The LLM reads it, calculates a "Conviction Score" (1-10), determines overall sentiment (Bullish/Bearish), and extracts the top 3 most important headlines using strict Native JSON mode.

## 🗄️ Database Models (PostgreSQL)

This service automatically creates and manages two tables using SQLAlchemy. We use an **Upsert (Update or Insert)** strategy. This means if you analyze `AAPL` on Monday, and analyze it again on Friday, it overwrites the Monday record to prevent duplicates. There is never more than 1 row per stock ticker!

1.  **`AIAnalysis` (`ai_analyses` table):** Stores the complete JSON output generated by the Gemini model, including overall sentiment, conviction score, and the AI's summary.
2.  **`StockNews` (`stock_news` table):** Extracts and stores *only* the top headlines generated by the AI for quick access by the frontend.

## 🔌 API Endpoints

You can interact with this service and test all endpoints via the interactive Swagger UI at **`http://localhost:8002/docs`**.

### 1. Check Health
*   **`GET /health`**
*   **Description**: A simple ping to verify that the Docker container is alive and responding to traffic.

### 2. Trigger AI Analysis
*   **`POST /analyze`**
*   **Body**: `{"ticker": "AAPL"}`
*   **Description**: This is the main engine. It triggers the LangGraph agent to use its tools, query Gemini, and generate the final JSON. It then automatically **upserts** the results into the `ai_analyses` and `stock_news` database tables. *(Note: Runs in a background thread to prevent API blocking).*

### 3. Fetch Historical Analysis
*   **`GET /history/{ticker}`**
*   **Description**: Bypasses the AI and queries the PostgreSQL database directly. Returns the saved AI analysis for the requested stock.

### 4. Fetch Stock News
*   **`GET /news/{ticker}`**
*   **Description**: Bypasses the AI and queries the PostgreSQL database directly. Returns just the top headlines that were saved for the requested stock.

## ⚠️ Production & Cost Considerations (Automated vs On-Demand)

Currently, this API operates on an **On-Demand** basis. The AI is only triggered, and the database is only updated, when a user explicitly calls the `/analyze` endpoint. This is the safest and most cost-effective architecture.

If you plan to automate this service using a background task runner like **Celery Beat**, please follow these rules to protect your API limits and avoid massive cloud billing charges:

1. **Beware API Costs:** Every call to `/analyze` hits Gemini, NewsAPI, and Twitter. Scanning 50 stocks every hour equals 1,200 AI requests per day, which will rapidly burn through free-tier limits.
2. **Beware Rate Limits:** Firing 30 requests at the exact same second will trigger `429 Too Many Requests` errors and get your IP blocked by Google.
3. **Best Practices for Celery:**
   * **Run Rarely:** Only schedule Celery to run 1-2 times a day (e.g., Market Open and Market Close).
   * **Limit Scope:** Only automate the top 5-10 stocks that are most important to your users.
   * **Add Delays:** Introduce a `time.sleep(10)` between each stock in your Celery task to respect rate limits.

## 🐳 Docker Deployment

Because this service relies on a shared PostgreSQL database, it runs inside a shared Docker network (`trading_network`).

If you add new dependencies to `pyproject.toml`, make sure you also add them to the `RUN uv pip install` line in the `Dockerfile` before rebuilding!

```bash
# To rebuild and restart the service
docker-compose down
docker-compose up -d --build ai-service
```
