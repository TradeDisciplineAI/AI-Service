# 🤖 AI-Service (Agent 1 & Agent 2)

This microservice is a FastAPI application that acts as an autonomous **AI Research Assistant** and **Market Scanner**. It uses **LangGraph** and **Google Gemini 1.5 Flash** to automatically scour the web, read financial news, analyze 5-minute intraday price action, gauge social media sentiment, and summarize market data for any stock ticker you give it. 

It is fully containerized, uses a persistent PostgreSQL database to store its findings, and exposes its features through a lightning-fast API.

---

## 🏗️ Architecture & File Structure

This service is cleanly structured using modern Python and FastAPI best practices to keep the code organized and scalable:

*   **`src/main.py`**: The main entry point that boots up the Uvicorn server and wires all the routes together.
*   **`src/routers/routes.py`**: Contains all of the API endpoints (`/scan`, `/analyze`, `/history`, `/news`).
*   **`src/database.py`**: Manages the SQLAlchemy connection to our shared PostgreSQL database (`shared_test_db`) and defines the table structures.
*   **`src/schemas.py`**: Contains Pydantic models (blueprints) to validate incoming API requests and ensure users send the correct data format.
*   **`src/agent1_graph.py`**: The LangGraph workflow for Agent 1 (Market Scanner).
*   **`src/agent2_graph.py`**: The LangGraph workflow for Agent 2 (News & Sentiment).
*   **`src/tools/`**: Contains the custom API integrations (`yfinance_tool.py`, `news_api_tool.py`, etc.).

---

## 🛠️ Core Technologies Used

*   **FastAPI:** Powers the high-performance API endpoints and automatic Swagger documentation.
*   **LangGraph & LangChain:** Orchestrates the AI's "thought process" and manages the state between gathering data and analyzing it.
*   **Google Gemini 1.5 Flash:** The core Large Language Model (LLM) that reads all the raw data and extracts insights, sentiment, and conviction scores.
*   **SQLAlchemy (ORM):** Manages the Python-to-PostgreSQL database connection and enforces data integrity.
*   **PostgreSQL:** The shared database engine (`shared_test_db`) where historical analyses and news are permanently stored.
*   **uv:** A blazing fast Python package installer used during the Docker build process.
*   **Docker:** Containerizes the service so it runs consistently anywhere and communicates via the `trading_network`.

## 🧠 The LangGraph Agent Workflows

This service currently houses two autonomous trading agents that communicate with each other via the PostgreSQL database.

### Agent 1: Market Scanner (The Eyes)
1.  **Gather Data Node**: Uses the `yfinance_tool` to pull mathematically perfect 5-minute OHLCV intraday candles for the requested stock.
2.  **Analyze Node**: Passes the data to Gemini 1.5 Flash to intuitively detect `breakouts`, `reversals`, `volume surges`, and `key support/resistance levels`. It returns a strict JSON package containing both the AI flags and the raw 5-minute candles.

### Agent 2: News & Sentiment (The Ears)
1.  **Gather Data Node**: Activates 3 tools simultaneously (`NewsAPI`, `Reddit`, `Twitter`) using a `ThreadPoolExecutor` to pull raw JSON data concurrently for maximum speed.
2.  **Analyze Node**: Gemini reads all the text and outputs a "Conviction Score" (1-10), overall sentiment (Bullish/Bearish), and top 3 headlines in Native JSON mode.

## 🗄️ Database Models (PostgreSQL)

This service automatically creates and manages three tables using SQLAlchemy. We use an **Upsert (Update or Insert)** strategy. This means if you analyze `AAPL` on Monday, and analyze it again on Friday, it overwrites the Monday record to prevent duplicates. There is never more than 1 row per stock ticker!

1.  **`MarketSignals` (`market_signals` table):** Stores the Agent 1 technical analysis output (Breakouts, Reversals, Support/Resistance, and raw 5-minute OHLCV candles).
2.  **`AIAnalysis` (`ai_analyses` table):** Stores the Agent 2 JSON output generated by the Gemini model, including overall sentiment, conviction score, and the AI's summary.
3.  **`StockNews` (`stock_news` table):** Extracts and stores *only* the top headlines generated by Agent 2 for quick access by the frontend.

## 🔌 API Endpoints

You can interact with this service and test all endpoints via the interactive Swagger UI at **`http://localhost:8002/docs`**.

### 1. Check Health
*   **`GET /health`**
*   **Description**: A simple ping to verify that the Docker container is alive and responding to traffic.

### 2. Trigger Agent 1 (Market Scanner)
*   **`POST /scan`**
*   **Body**: `{"ticker": "AAPL"}`
*   **Description**: Triggers Agent 1 to pull live 5-minute charts, detect breakouts using AI, and **upserts** the JSON into the `market_signals` database table. *(Runs in background thread)*.

### 3. Trigger Agent 2 (News & Sentiment)
*   **`POST /analyze`**
*   **Body**: `{"ticker": "AAPL"}`
*   **Description**: Triggers Agent 2 to use its tools, query Gemini for sentiment, and **upsert** the results into the `ai_analyses` and `stock_news` tables. *(Runs in background thread)*.

### 3. Fetch Market Signals
*   **`GET /market-signals/{ticker}`**
*   **Description**: Bypasses the AI and queries the PostgreSQL database directly. Returns the most recent 5-minute OHLCV data and Breakout JSON saved by Agent 1.

### 4. Fetch Historical Analysis
*   **`GET /history/{ticker}`**
*   **Description**: Bypasses the AI and queries the PostgreSQL database directly. Returns the saved AI analysis for the requested stock.

### 5. Fetch Stock News
*   **`GET /news/{ticker}`**
*   **Description**: Bypasses the AI and queries the PostgreSQL database directly. Returns just the top headlines that were saved for the requested stock.

## ⚙️ Background Automation & Math Pre-Filtering

This service is fully integrated with **Celery Beat** (running inside the `market-service`). It operates completely autonomously using a **Hybrid Analysis Approach** to protect API limits and reduce server costs.

### How the Automation Works
1. **Dynamic Portfolio Syncing:** Every 5 minutes, Celery queries the main PostgreSQL database to find exactly which unique stocks active users hold in their portfolios (`PortfolioHolding` table).
2. **The Math Pre-Filter:** Celery sends those unique symbols to the `/scan` endpoint. The `yfinance_tool` downloads the 5-minute candles and runs a pure-math check:
   * *Did the price move significantly in the last 5 minutes?*
   * *Is the volume 1.5x higher than average?*
3. **The AI Trigger:** If the math filter fails (the stock is moving sideways), Agent 1 aborts the scan immediately, saving API credits. If the math filter passes (a volume surge or price jump is detected), it triggers **Gemini 1.5 Flash** to analyze the chart and detect Breakouts/Reversals.

This architecture reduces AI API calls by over 90% while guaranteeing that the moment a user adds a stock to their portfolio, it is actively monitored for breakouts!

## 🐳 Docker Deployment

Because this service relies on a shared PostgreSQL database, it runs inside a shared Docker network (`trading_network`).

If you add new dependencies to `pyproject.toml`, make sure you also add them to the `RUN uv pip install` line in the `Dockerfile` before rebuilding!

```bash
# To rebuild and restart the service
docker-compose down
docker-compose up -d --build ai-service
```
